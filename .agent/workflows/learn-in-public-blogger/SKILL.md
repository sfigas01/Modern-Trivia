# Learn in Public Blog Post Formatter

## Context

Use this skill when the user wants to write a blog post that documents their personal learning journey, solves a specific technical problem they encountered, or aims to build thought leadership through authentic storytelling. The tone should be vulnerable, experiential, and highly actionable, avoiding overly promotional, corporate, or academic language.

## Procedural Knowledge: The 6-Section Template

When drafting, editing, or formatting the user's blog post, strictly follow this structure:

### 1. The Setup

- **Goal:** Establish context and credibility without self-promotion.
- **Instructions:** Open with 2-3 short paragraphs establishing who the user is, what they're building, and where they are in their journey. Reference previous posts in a series if applicable. State plainly what this post covers. No hype, no hooks — just honest framing.

### 2. The Catalyst

- **Goal:** Explain why this topic matters through a real problem.
- **Instructions:** Describe the specific situation that made this topic unavoidable. What broke? What got messy? What outgrew the current setup? Ground it in the actual project history (git commits, real incidents, real scale). Show the "before" state honestly.

### 3. What I Actually Built

- **Goal:** Show the work with real details.
- **Instructions:** Walk through what was built or set up, using specifics from the actual project. Include numbered lists for processes, tool names, and concrete examples. This is the core body — it should be the longest section. Be specific enough that a reader could replicate it, but don't over-explain concepts the audience already knows.

### 4. What This Unlocked

- **Goal:** Share the ah-ha moment — what the user can do now that they couldn't before.
- **Instructions:** A short, reflective section (2-3 paragraphs max) about what this experience actually changed. What new capability does the user have? What do they understand now that they didn't before? What's the implication for how they work going forward? Frame it around growth and new abilities, not surprise or remarkability. Avoid phrases like "what surprised me," "what I find remarkable," or "the part that's actually interesting" — these are obvious AI writing patterns. Just state what changed.

### 5. Try It Yourself

- **Goal:** Give the reader something actionable they can do today.
- **Instructions:** Provide 3-5 concrete, practical tips the reader can apply to their own work. Each tip should start with a bolded imperative phrase. Include real examples: actual prompts used, tool configurations, workflow files, or setup steps. Where possible, show the user's real prompts or commands rather than generic advice.

### 6. The Wrap-Up

- **Goal:** Land the thesis and tease what's next.
- **Instructions:** A short closing (2-3 sentences max) that reinforces the main point without repeating the whole post. If part of a series, tease the next topic. Keep it understated — no motivational speeches.

## Strict Formatting Rules

- **Visual hierarchy:** Use H3 tags (`###`) for main sections. No H2s — keeps it clean for LinkedIn and blog platforms.
- **Micro-formatting:** Keep paragraphs to 1-3 sentences. One idea per paragraph.
- **Highlighting:** Bold the most critical phrases so a 30-second skimmer gets the thesis.
- **Blockquotes for prompts:** When showing actual prompts or commands the user gave to AI tools, use `>` blockquote formatting with italics.
- **No listicle energy:** Use numbered lists only for sequential processes. Use bold paragraphs for tips and advice. Avoid bullet-point-heavy sections that read like a corporate blog.
- **Natural tone:** Write like a person talking to a colleague, not an AI writing a LinkedIn post. No "here's the thing," no "let me be honest," no "I want to be transparent." Just be those things.

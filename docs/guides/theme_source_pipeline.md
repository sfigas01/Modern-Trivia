# Theme evidence eligibility policy kernel

`server/lib/theme-evidence-eligibility.ts` makes a synchronous, deterministic decision over a complete caller-supplied graph: the live question snapshot, its immutable revision, all reviews for that revision, reviewed fact revisions, cited passages and documents, and fact-to-passage bindings. It performs no retrieval, database access, model call, or factual judgment. This is an S1 policy slice; no route or generation flow calls it yet.

The caller injects `now` and an explicit policy containing current source, extractor, review, and prompt versions; allowed source classes; maximum document and review ages; and the minimum number of independent origin groups **per reviewed fact**. Null expiry means the relevant age limit still applies. Expiry is exclusive: evidence is stale at its `validUntil` timestamp.

Question content hashes use SHA-256 of the complete `QuestionContentSnapshot`, serialized as JSON with object keys sorted recursively and array order preserved. `hashQuestionSnapshot` exposes that encoding for future writers. Eligibility requires the live snapshot, live content hash, revision snapshot, revision content hash, and selected review binding to agree exactly. A content change needs a new revision and review.

All supplied reviews are structurally checked before selection, so a malformed later row cannot expose an older pass. For the exact revision, the latest review sorts by descending `reviewedAt`, then descending review UUID for a stable timestamp tie. A newer adverse review, wrong policy version, or expired review withholds; the evaluator does not fall back to an older pass. Every one of the seven review dimensions must pass and cite a passage bound to a reviewed fact with a supporting edge. Any conflict edge for a reviewed fact withholds even if that passage was omitted from the review citations. Each cited passage must resolve to a current, allowed document, and every reviewed fact must have enough distinct supporting `originGroup` values among its citations.

The reviewed fact must also be the latest supplied revision of its fact identity. At least one reviewed fact's canonical answer must equal the question answer. Every accepted answer must be that answer or a supported alias on an answer-bearing fact; a separate contextual fact cannot expand the accepted-answer set. The source adapter must supply the full revision and conflict set for these checks; an incomplete graph cannot establish eligibility.

The decision returns a typed reason and a `theme-eligibility-v1` fingerprint. The fingerprint hashes the validated graph and policy in stable ID order, so evidence or policy mutation invalidates a prior decision without depending on database row order. It does not grant lasting authorization: a caller must reevaluate with the current time and graph before activation or reservation. The kernel cannot verify the bytes behind a document's stored hash or establish that a passage actually entails a claim; those require source retrieval, independent review, and evaluation work outside this slice.
